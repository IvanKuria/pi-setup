# SWE Intern Workflow

## Before Coding

Clarify:
- what the ticket asks for
- how the system currently behaves
- what the smallest safe change is
- what files/classes are likely involved
- how to test it

## During Coding

- Keep changes boring and reviewable.
- Prefer matching local style over introducing personal style.
- Commit mentally in small chunks: inspect, change, test, summarize.
- If uncertain, produce options with tradeoffs rather than guessing.

## Before Review

Prepare:
- concise PR summary
- test evidence
- risk/rollback note
- explanation of why the design is intentionally small

## Learning Prompts

Ask:
- What would a senior reviewer question?
- What concept did this ticket teach me?
- How do I explain this in standup?
- What should I inspect next to understand this area better?
